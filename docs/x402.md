# x402: pay per call (phase 15)

From the product doc: "Swarms and API callers: agents and software pay per call with no API keys or prepaid accounts, which suits pay-per-run pricing", and "x402 for agents and power users". Business owners keep paying with credits by card; nothing changes for them.

x402 is the open standard that brings back HTTP 402 Payment Required: a server answers with the price, the caller pays, and sends the request again with proof of payment. WOVI takes it on the two start endpoints of the REST API ([api.md](api.md)). A paid run is checked, held, gated, charged and settled exactly like a run with credits ([credits.md](credits.md)).

Nothing here moves money on its own. WOVI only receives: there is no private key anywhere in this code. Refunds are recorded for the owner to send from their own wallet. Tests and the demo use the fake verifier and a pretend chain; no test calls a chain.

The code lives in `src/lib/x402/`.

| File | What it holds |
|---|---|
| `config.ts` | Every setting, read from the environment, and `x402Status`: on or off, and what is missing. |
| `money.ts` | Exact math in whole units: wei for ETH, micro-dollars for USD, prices with 8 decimals. |
| `protocol.ts` | X-PAYMENT in and X-PAYMENT-RESPONSE out (base64 JSON), the message a payer signs, the body hash. |
| `verifier.ts` | The `PaymentVerifier` interface, the shared checks (`checkTransfer`), the fake verifier and its pretend chain. |
| `onchain.ts` | The on-chain verifier for Robinhood Chain (viem, read only) and the Chainlink price reader. |
| `service.ts` | `X402`: quotes, paying, starting the run, settling, refunds owed, receipts, discovery, the owner's summary. |
| `http.ts` | `X402Http`: the part of `/api/v1` that needs no key. |
| `openapi.ts`, `schemas.ts` | x402 in the OpenAPI document, as zod schemas. |
| `store.ts`, `types.ts` | Five tables (`.data/x402.json`): `quotes`, `payments`, `refunds`, `receipts`, `fakeTransfers`. |
| `words.ts` | Words for the owner's page. |

Routes: `src/app/api/v1/[[...path]]/route.ts` (through `RestApi`, unchanged), `src/app/.well-known/x402/route.ts`, the owner's page `src/app/app/settings/x402/`.

## Switching it on

x402 is **off** until all three are set. Off, a call without a key gets `401 unauthenticated`, as before.

```
WOVI_X402_PAY_TO=0xYourReceivingAddress          # where payers send money
WOVI_X402_RPC_URL=https://your-robinhood-chain-rpc  # to check each payment on chain
WOVI_X402_ETH_USD_FEED=0xChainlinkEthUsdFeed     # the ETH price: a Chainlink feed on the chain,
# or WOVI_X402_ETH_USD=<a fixed USD price per ETH>
```

| Setting | Default | Meaning |
|---|---|---|
| `WOVI_X402_PAY_TO` | empty | The receiving address. Empty: off. |
| `WOVI_X402_RPC_URL` | empty | Robinhood Chain JSON-RPC for the on-chain verifier. Empty: off. |
| `WOVI_X402_ETH_USD_FEED` | empty | A Chainlink USD feed address on the chain. Older than 26 hours: no quote. |
| `WOVI_X402_ETH_USD` | empty | A fixed USD price per ETH instead of a feed. It goes stale; prefer the feed. |
| `WOVI_X402_VERIFIER` | `onchain` | `fake` for local demos only. Refused off this machine. |
| `WOVI_X402_ASSETS` | ETH | A JSON list replacing the assets, to add a stablecoin (below). |
| `WOVI_X402_CHAIN_ID` | 4663 | Robinhood Chain. The network is `eip155:<id>`. |
| `WOVI_X402_MIN_CONFIRMATIONS` | 3 | Blocks before a paid run starts. |
| `WOVI_X402_QUOTE_SECONDS` | 600 | How long a quote stays open. |
| `WOVI_X402_REFUND_FROM_CREDITS` | 5 | After a run that worked, unused money is owed back from this many credits up. |

Adding a stablecoin next to ETH:

```
WOVI_X402_ASSETS='[{"symbol":"ETH","address":"0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE","decimals":18,"price":{"kind":"chainlink","feed":"0x..."}},
                   {"symbol":"USDC","address":"0xTheTokenOnRobinhoodChain","decimals":6,"price":{"kind":"stable"}}]'
```

ETH is `0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE` (EIP-7528). A token is read from its `Transfer` logs.

## How a call is paid

```
POST /api/v1/agents/hook-writer/runs        (no Authorization)
  <- 402 { x402Version: 1, code: "payment_required", accepts: [ PaymentRequirements ] }
the payer sends accepts[0].maxAmountRequired to accepts[0].payTo on Robinhood Chain
the payer signs accepts[0].extra.sign with the transaction hash filled in (EIP-191)
POST /api/v1/agents/hook-writer/runs        X-PAYMENT: base64(PaymentPayload), the same body
  <- 202 the run, X-PAYMENT-RESPONSE, X-Receipt-Token, Location: /api/v1/x402/runs/{id}
GET /api/v1/x402/runs/{id}                  Authorization: Bearer wovi_rt_...
  <- { run, payment }
```

Pipelines are the same at `POST /api/v1/pipelines/{id}/runs`, read at `/x402/pipeline-runs/{id}`, with `/pick` and `/cancel`.

**The 402.** Each entry in `accepts`:

```json
{
  "scheme": "tx-hash",
  "network": "eip155:4663",
  "maxAmountRequired": "16000000000000",
  "resource": "https://.../api/v1/agents/hook-writer/runs",
  "description": "Hook Writer: one run, about 4 credits ($0.04). Never charged more; ...",
  "mimeType": "application/json",
  "payTo": "0x...",
  "maxTimeoutSeconds": 600,
  "asset": "0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE",
  "outputSchema": null,
  "extra": { "nonce": "x402q_...", "expiresAt": "...", "chainId": 4663, "symbol": "ETH", "decimals": 18, "credits": 4, "priceUsd": "0.04", "sign": "WOVI x402 payment\nNonce: x402q_...\nTransaction: {txHash}\nChain: 4663" }
}
```

**The price** is the call's estimate in credits, the same number the app and the API show ([credits.md](credits.md#pricing)), at one credit = $0.01, converted to the asset when the 402 is made and rounded up to whole wei: `ceil(usd micro x 100 x 10^decimals / price with 8 decimals)`. `maxCredits` in the body lowers the quote, never raises it.

**X-PAYMENT** is base64 of:

```json
{ "x402Version": 1, "scheme": "tx-hash", "network": "eip155:4663",
  "payload": { "nonce": "x402q_...", "txHash": "0x...", "payer": "0x...", "asset": "0xEeee...EEeE", "signature": "0x..." } }
```

**X-PAYMENT-RESPONSE** is base64 of `{ success, transaction, network, payer, errorReason? }`, on every answer to a paid try.

**The receipt token** (`X-Receipt-Token`, `wovi_rt_...`, kept as a hash, 30 days) reads that one run and its payment, stops it, or picks in a pipeline. It opens nothing else.

## Why our own scheme, and not the official packages

The official packages (`@x402/core`, `@x402/evm`, v2, maintained; `x402` v1, last changed April 2026) implement the `exact` scheme on EVM: the payer signs a token transfer (EIP-3009 or Permit2) and a **facilitator** submits it on chain with its own wallet and pays the gas. That does not fit here:

- WOVI takes ETH, and ETH has no signed transfers.
- Submitting a transfer needs a wallet with a key on the server. WOVI holds no keys.
- No public facilitator covers Robinhood Chain (4663), and calling one would be a network call at runtime.

So WOVI keeps the x402 version 1 wire format (the 402 body, X-PAYMENT and X-PAYMENT-RESPONSE as base64 JSON) with its own scheme, `tx-hash`: the payer sends the transfer themselves, and X-PAYMENT carries the transaction hash, signed by the wallet that sent it together with the quote's nonce. The signature means a hash seen on chain is useless to anyone but its sender. Verification is our own code in `verifier.ts` and `onchain.ts`, and fetches nothing beyond the owner's RPC. The network is written as CAIP-2 (`eip155:4663`), as x402 v2 does, since v1's named networks do not include Robinhood Chain. When a facilitator supports the chain and a stablecoin, `exact` can sit beside `tx-hash` as another entry in `accepts`.

## The checks

In this order. Each failure is a 402 with a `code`, the reason in `error`, and a quote to pay (the same quote when trying again later makes sense, a fresh one otherwise).

| Check | Code |
|---|---|
| X-PAYMENT is base64 JSON, version 1, scheme `tx-hash`, a nonce, a 64-hex hash, addresses, a signature | `payment_invalid` |
| The network is ours | `payment_wrong_chain` |
| The nonce is a quote from this server | `payment_unknown_quote` |
| The quote is for this method, path and body (a hash of the body in canonical JSON) | `payment_wrong_resource` |
| The quote was not used | `payment_used` |
| The quote's time plus a grace of 15 minutes has not passed | `payment_expired` |
| The transaction never paid before | `payment_used` |
| The asset is one the quote offered | `payment_wrong_asset` |
| The signature of the quote message recovers to `payer` | `payment_bad_signature` |
| The transaction exists (else try again) | `payment_not_found` |
| The RPC is chain 4663, the transaction succeeded | `payment_wrong_chain`, `payment_failed` |
| It was sent by `payer`, to `payTo`, in that asset | `payment_wrong_payer`, `payment_wrong_recipient`, `payment_wrong_asset` |
| It has enough confirmations (else try again, `Retry-After: 5`) | `payment_not_confirmed` |
| It was mined after the quote was made (2 minutes of clock skew) | `payment_too_old` |
| It was mined before the quote ended | `payment_too_late` (owed back) |
| It is at least the quote | `payment_amount_too_low` (owed back) |

A transfer that reached the owner but came too late or too short is recorded as a payment with status `rejected`, uses up its transaction and quote, and is owed back in full.

**Replay.** The quote's nonce and the transaction hash are each used once (the payment id is `<chain>:<hash>`, a primary key; the quote is claimed with a conditional update). Paid tries for one quote run one at a time. The **same X-PAYMENT header again** (a client that lost the answer) returns the same run with `200` and a new receipt, never a second run or charge. Anything else that reuses a nonce or a transaction is `payment_used`.

## Accounting

Every paid run lives in one workspace, **`ws_x402`** ("x402 payments"), started as a key-like caller (`keyId: "x402"`, role editor) that may run agents and nothing more, counting toward the account `usr_x402`. Nobody signs in as either. Each payment row records the payer, the asset, the amount required and paid (wei), the transaction, its block and time, the quote, the verifier and the run.

The credits ledger of `ws_x402`, for one run that held 4 and cost 1:

```
top_up       +4   x402:<payment>      the quote, as credits
hold         -4   the run holds its estimate (never above the quote)
release      +4   and when it ends
charge       -1   its real price, never above what it held
adjustment   -3   what it did not use leaves again; the workspace holds nothing between calls
```

**Settling** happens when the engine reports the run ended (or a pipeline is ready, failed or stopped), and again after a restart for anything left open.

- The charge in wei is `floor(required x charged / quoted)`, at the quote's own rate, never above what was paid.
- What is left (`paid - used`, including any overpayment) is **owed back**:
  - always after a failed or stopped run, and when a paid run could not start (`not_started`);
  - after a run that worked, from `WOVI_X402_REFUND_FROM_CREDITS` (5) credits' worth up. Less stays with the owner, since sending it back costs more than it is worth, and the quote said the call costs up to that much.
- An owed refund goes through the verifier's `refund()`, which only makes the record: to whom, how much, in what, why. Nothing is sent. On the owner's page each one has a field for the transaction the owner sent it with ("Mark paid"); WOVI records it and checks nothing.

## Discovery

- `GET /api/v1/x402` and `GET /.well-known/x402` (no key, CORS open): on or off, test or not, the scheme, network, receiving address, assets, quote time, confirmations, every agent and pipeline with its price in credits and USD, the receipt endpoints, how to pay, and that MCP stays on keys.
- The OpenAPI document: the two start operations have `security: [{ apiKey: [] }, {}]` (a key, or nothing), an `x-x402` block, a `402` that is `Error` or `PaymentRequired`, and the `X-PAYMENT-RESPONSE` and `X-Receipt-Token` headers on `202`. The x402 paths are under the `x402` tag with a `receipt` bearer scheme. Schemas: `PaymentRequired`, `PaymentRequirements`, `PaymentPayload`, `SettleResponse`, `X402Payment`, `X402RunResult`, `X402PipelineRunResult`, `X402Discovery`.
- The API reference page has a "Pay per call with x402" section with every endpoint and its price.

**MCP stays key-based.** `/mcp` answers 401 without a key, with x402 on or off. MCP clients authenticate once per session and do not handle a 402 per tool call today; x402 on MCP waits until clients do.

## Safety

- **Off by default**, and off unless the receiving address, a way to check payments and a price are all set. The fake verifier is refused off this machine.
- **No keys.** Nothing signs or sends. The RPC is read only. Refunds are records.
- **Limits** (in memory, per process, like the API's): 60 quotes a minute per address, 30 paid tries a minute per address, 20 a minute per paying wallet, 240 receipt reads a minute per address. Over: `429` with `Retry-After`.
- **Quotes expire** after 10 minutes; a transfer must be mined inside that window. Unused quotes are swept a day after they end.
- **Exact amounts:** bigint wei throughout, prices with 8 decimals, rounding up for the owner on quotes and down for the payer on charges.
- The request is checked (agent, inputs, no Brand Brain) **before** a quote, so nobody pays for a call that cannot run. A paid call that still does not start is owed back in full.
- x402 runs have no Brand Brain (there is no workspace to hold one) and cannot be seen with any API key.

## The owner's page

**Settings, x402 payments** (`/app/settings/x402`), for owners of WOVI only (owners of the platform workspace; anyone else gets 404). It shows on or off and what is missing, the receiving address, network, assets, verifier and rules, the switch-on lines while off, totals (payments, received, owed back, refunds to send), recent payments (call, payer, transaction, paid, credits charged of quoted, state) and every refund to send with "Mark paid". In test mode it says so at the top. The Settings page links to it for owners.

`x402-demo.mjs` makes a wallet in memory (never printed or saved), and through the local server: reads discovery, gets a 402, "sends" the transfer with `POST /api/v1/x402/dev/transfers` (the fake verifier's pretend wallet, local only), signs, pays, reads the run with its receipt, replays the same header, reuses a transfer, underpays, stops a paid run, and pays for a pipeline with a pick. It writes `~/WOVI-x402-screens/x402-demo.txt`. The screenshots go to `~/WOVI-x402-screens/`. The receiving address there is a placeholder; nothing is ever sent to it.

## Tests

`src/lib/x402/x402.test.ts` (19 tests), all on the fake verifier or a stub RPC reader:

- off by default: no address, no RPC, no price, a bad address, the fake verifier off this machine; a start without a key stays 401 and no quote is made; discovery says off;
- the 402: the x402 shape parsed with its schema, the price from the credits estimate in exact wei, the nonce, expiry and stored quote, `maxCredits`; inputs, Brand Brain, unknown agents and bad JSON refused before any quote;
- paying: the run started, X-PAYMENT-RESPONSE and the receipt, the payment recorded with payer, amount and transaction, charged no more than quoted, the ledger back to zero, the quote used; the receipt reading only its run; API keys never seeing x402 runs; unused money owed back over the minimum;
- replay: the same header returns the same run; a reused transaction or quote refused;
- refusals: too little (owed back), wrong recipient, chain, asset, payer, a failed transaction, another wallet's signature, another body, another network, an unknown nonce, bad base64; the quote still working after;
- time: not enough confirmations (try again, same quote), a transfer after the quote ended (owed back), one before the quote, an expired quote with a fresh one;
- refunds: a failed run owed back in full, a run stopped with its receipt, a run that could not start, marking a refund paid once;
- a pipeline paid, picked with its receipt and settled when ready;
- limits per address and per wallet; discovery with prices; MCP still 401 without a key; keys unaffected;
- the OpenAPI document; the money math; the shared transfer rules; the on-chain reader for ETH, tokens, a wrong chain, a missing transaction and the Chainlink feed with a stub reader; strict X-PAYMENT parsing.
