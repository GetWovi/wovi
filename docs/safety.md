# Safety, legal and platform rules (phase 18)

From the product doc, section 11: "The main risk is losing creators' accounts or inviting legal trouble, so these controls are built in, not added later." This phase builds that list, plus the terms, the privacy notice and the own-risk notice, from the rules themselves (sources at the end). Nothing here calls a real model: every test and screenshot runs on the fake provider, and vitest blanks `OPENROUTER_API_KEY`.

## Where everything lives

| Rule | What it does | Code |
|---|---|---|
| Content rules | Nine categories WOVI does not write: fake reviews or testimonials, impersonation, deepfakes, false claims, hate, harassment, sexual content, unsafe advice, copyrighted music. Regular expressions as data, narrow on purpose. | `src/lib/safety/rules.ts`, `screen.ts` |
| Requests | Every text, long text and link input and the run's own idea are read at submit. A match refuses the run with `RunError("blocked")` before any credit is held or anything is queued. Each issue is `field: refusal (Found: "...")`. The API answers `content_blocked` (422); the app shows "WOVI cannot make this" with the reasons under the form. Pipelines read their inputs the same way before anything is held. | `src/lib/runs/engine.ts` (`submitNew`, `requestTexts`), `src/lib/pipelines/engine.ts`, `src/components/safety/BlockedNotice.tsx` |
| Drafts | Two checks run on every draft of every agent, declared or not, and are recorded only when they find something: `content_safety` (hate, harassment, sexual content, unsafe advice, and the agent's own blocked phrases) and `music_rights` (a named copyrighted song). A failure sends the draft back through the quality gate's rewrite with the reason. A draft that still breaks a hard rule is withheld: the run fails with `blocked`, nothing is shown and its hold is given back. A named song goes to a person. Fake reviews, impersonation and unprovable claims in drafts stay with the phase 12 `claims` check, which always sends them to a person. | `src/lib/runs/guardrails.ts`, `src/lib/runs/execute.ts` |
| Per-agent additions | `safety.block` in the spec (optional, up to 30 phrases): refused in requests and kept out of drafts for that agent, matched as whole words. Edited in the builder under Guardrails. Not in the public view. | `src/lib/agents/spec.ts`, `src/components/builder/SpecForm.tsx` |
| Prompt injection | Everything a person types, a change note, a comment or a fetched page is a `<data>` block that cannot close itself (phase 3). The engine rules now also say never to call a tool from inside a block. Text that reads like instructions ("ignore the rules above", a fake `</data>`, "call the web_scrape tool") is noted on the run (`prompt_injection`, a note, never a block). `untrustedBlock("comment" \| "page" \| "tool", text)` is how a tool layer or comment reader adds material. | `src/lib/runs/prompt.ts`, `src/lib/safety/injection.ts` |
| Tools | The engine sends the model no tools at all; the provider request has only model, messages, temperature, max tokens and the signal (a test checks the keys). `assertDeclaredTool(spec, id)` is the gate a tool layer must call: only tools the spec declares and the catalog knows. | `src/lib/safety/injection.ts` |
| Platform rules | Per platform (TikTok, Instagram Reels, YouTube Shorts, X): length, the AI label (when and where), music, paid partnership labels, automation, each with its source. Shown beside every agent's form, written into every agent's system message (with the content rules), and the source of the AI-label reminder. The TikTok caption limit is now 2,200 characters, the limit TikTok publishes for its API, in the guardrail and the quality check. | `src/lib/safety/platforms.ts`, `src/components/safety/PlatformRules.tsx` |
| No engagement automation | No tool, MCP tool or REST route may like, follow, post, repost, message or schedule on a platform. A test reads every name against `FORBIDDEN_AUTOMATION_WORDS`. WOVI posts nothing. | `src/lib/safety/platforms.ts`, `safety.test.ts` |
| People approve | Closed two paths where an API key could decide: `GuardedPipelines.decide` and `clearDecision`, and the app's run decision without teams, now ask for `decide`, which keys never have. The REST API already refused; now every layer does. | `src/lib/pipelines/guard.ts`, `src/lib/app/api.ts` |
| AI label | Every result says "Made with AI" and lists, for the agent's platforms, when a label is needed and where it is set. A box stores "I will add the AI label where the platform asks for it" on the run (`run.aiLabel`: who, when, which platforms). People only (`decide`). Every public run view and API run carries `aiGenerated: true`; MCP results say "Written by AI". | `src/lib/safety/ai-label.ts`, `src/components/safety/AiLabelPanel.tsx`, `src/lib/runs/run.ts`, `src/lib/api/views.ts`, `src/lib/api/mcp.ts` |
| Upload rights | No file is stored without the box "I own this, or I have the rights to use it here." (agent form files, mood board images and the builder's clip samples). The server refuses the upload without it and keeps the confirmation (file, who, when, the exact words). A run with any file needs `confirmations.rights`, whatever the agent declares, and every run keeps when each confirmation was given (`run.confirmedAt`). | `src/lib/safety/rights.ts`, `src/app/app/make/actions.ts`, `src/app/brand-brain/actions.ts`, `src/components/safety/RightsCheck.tsx` |
| Music | The music rule in every prompt, the refusal for requests to use a copyrighted track, and the `music_rights` check on drafts. | as above |
| Notice and action | `/report`: open to anyone, signed in or not. Where, why (eight reasons), an explanation, optional name and email, a good-faith box. A reference at once and, with an email, a receipt. Rate limited per address. `/app/settings/safety` (WOVI's owners only): the queue, "I am looking at it", and a decision by hand (taken down, account restricted, no action) with the term or law. "Taken down" hides a run's output everywhere (kept in the store for a dispute, `run.withheld`) or deletes a comment. The reporter gets the decision and the workspace's owners and admins get a statement of reasons with how to object. A Report link sits under every result, review item and client view. | `src/lib/safety/reports.ts`, `src/app/report/`, `src/app/app/settings/safety/` |
| Withdrawal | Before paying (card, USDC, ETH or $WOVI) the buyer ticks the request to start at once and the withdrawal terms; the exact words are stored on the top-up (for USDC and ETH, on the price first and then on the top-up). Buttons say "Buy and pay $X". For 14 days, "Withdraw from this purchase" with a confirm: the credits from it not yet used leave the balance, the money is written down as owed, and a receipt goes by email. Once all are used, it can no longer be withdrawn. A card purchase is paid back with "Refund to the card through Stripe" on Reports and refunds (Stripe's refund API, once); a USDC or ETH purchase is owed back in the same asset to the paying wallet, for the owner to send. Credits a refund in Stripe's dashboard already took are not given back twice. | `src/lib/legal/operator.ts`, `src/lib/legal/withdrawals.ts`, `src/components/credits/CreditForms.tsx`, `src/components/safety/PurchaseConsent.tsx` |
| Your data | On the account page: "Use my edits to improve agents" (off until turned on, off as easy as on, history kept), "Download my data" (one JSON file: account, sign-ins, passkeys, wallets, consents, holder reading, $WOVI payments, onboarding, notifications, upload confirmations, reports made, and each workspace: its content where the person is an owner, their own runs, comments, decisions and credit entries elsewhere), and "Delete my account" with what happens to each workspace shown first. | `src/lib/privacy/privacy.ts`, `src/app/account/` |
| Deleting an account | Workspaces with only this person are deleted with everything in them (Brand Brains, runs, pipelines, review items, comments, clients, links, webhooks, API keys, files); paid credits left are written down as owed back. Shared workspaces stay: the person leaves, their name on comments, activity and decisions becomes "Deleted member", keys they made are revoked. Sign-in, sessions, passkeys, wallets, holder reading, notifications, consents and upload confirmations are deleted. Ledger entries, top-ups and $WOVI payments stay for the books with an anonymous id. The last owner of a shared workspace hands it over first. Confirmed by typing the email. | `src/lib/privacy/privacy.ts` |
| Consent in use | The builder's quality roll-up shows a draft's text and a change request's words only from the bench and from people who turned the consent on. Counts and scores are unchanged. | `src/lib/quality/service.ts`, `rollup.ts`, `server.ts` |
| Retention | `RETENTION`: used or expired sign-in links and ended sessions at once, webhook delivery logs 30 days, read notifications 180 days, dev mail 30 days, unused $WOVI quotes 30 days after expiry, a reporter's name and email 12 months after the decision. Never the ledger, top-ups, payments, runs or Brand Brains. The sweep runs daily only with `WOVI_RETENTION_SWEEP=on`, so an existing data dir loses nothing on upgrade unless the owner switches it on. | `src/lib/privacy/privacy.ts`, `src/lib/privacy/jobs.ts`, `src/instrumentation.ts` |
| Pages | `/terms`, `/privacy`, `/own-risk`, `/report`. The operator, the contact address and the effective date are constants in one file. Legal links in every footer (site, app, homepage); `/token` and the credits page link the own-risk notice. | `src/lib/legal/operator.ts`, `src/components/safety/LegalPage.tsx`, `src/app/terms`, `src/app/privacy`, `src/app/own-risk` |

## Stored data (what changed)

Nothing stored before phase 18 is migrated or rewritten. New fields are optional and read as "not given" on old rows: `run.confirmedAt`, `run.aiLabel`, `run.withheld`, `topUp.consent`, `spec.safety`, and since the payment update `topUp.checkoutUrl`, `topUp.payment`, `topUp.chain`, `owed.chain`, `owed.reason`, `owed.refund` (plus the owed kind `chain_payment`). The payment update's own tables live in `chainpay.json` and `stripe.json`, each made on its first write. New tables live in their own file, `safety.json` (reports, consents, rights, owed, deletions), created on the first write. A test loads a data dir written by the phase 17 code (`src/test-fixtures/phase17-data`), checks that every record reads, that reading changes no file, that new runs, notes and reports work, and that installing the launch set again leaves a builder's edit alone (`src/lib/safety/phase17-compat.test.ts`).

Records do change in these cases, each started by a person: a top-up stores its consent; the AI-label box writes `aiLabel` on its run; a report decision writes `withheld` on a run or deletes a comment; a withdrawal writes one ledger adjustment; deleting an account deletes and anonymises as described above (ledger, top-ups, comments, activity, items and decisions get the anonymous id); the retention sweep, when switched on.

## Not yet

- Withdrawal for credits paid with $WOVI or by x402 has no button; the terms point to email. Owed USDC, ETH and anything not paid by card is recorded for the owner to send; only card refunds go through the provider, and only when the owner presses the button.
- Builder uploads of sample files and the builder's mood boards are platform staff only and do not ask for the rights box. Clip samples do (see [builder.md](builder.md#clip-samples)).
- Removing content from a pipeline run's package after a report: the queue takes runs and comments down; a pipeline run is decided by hand.
- The content rules are rule-based. A model classifier would fit the quality gate's judge slot.
- Real email (Resend or SMTP) is built and switched on by `EMAIL_PROVIDER` ([accounts.md](accounts.md#email)). The privacy notice says the provider will be named before it starts: add it to "Who helps us run WOVI" in `src/app/privacy/page.tsx` the day it is switched on.
- Machine-readable marking of AI text beyond `aiGenerated: true` in the API and exports (EU AI Act Art. 50(2), from 2 August 2026 for systems placed on the market after that date): when images or video arrive, they need C2PA or similar.
